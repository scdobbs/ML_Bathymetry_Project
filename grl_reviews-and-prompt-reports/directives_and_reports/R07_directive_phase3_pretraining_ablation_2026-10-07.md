## 1. Pretraining data

### 1.1 Blocks used

- **Reconstruction task:** every corpus block with cell size between **10 m and 256 m** (inclusive).
- **Sounding-spread task:** the subset of those blocks whose products are usable under the contract consumer rule
  (`available` and no flags).
- Report both counts, and the blocks excluded by the cell-size limits.

### 1.2 Cell-size sampling (pre-registered)

The corpus is skewed coarse: 60 % of blocks have cells above 87 m, while the development LR spans about 10–87 m and the
confirmatory units 103–151 m. To keep coarse blocks from dominating without dropping them:

- Bin blocks by log₂(cell) into 8 equal-width bins from log₂ 10 to log₂ 256.
- Sample a bin uniformly, then a block uniformly within the bin, then a window position uniformly within the block.
- Report blocks per bin and the effective share of training windows per bin.

### 1.3 Held-out pretext validation set

- Hold out **5 % of corpus cruises**, stratified by instrument family, chosen once with
  `numpy.random.default_rng(20261007)`. No window from a held-out cruise is used for pretraining.
- These cruises are used only to report pretext validation curves (§2.4). They are never used for checkpoint selection.

### 1.4 Windows in the development representation

Pretraining windows must be built **exactly** as development inputs are (R04 §7, R06 §1.2), with the block's
`grid.tif` in the role of `lr.tif`. There is no HR, so the HR pixel size is supplied as follows:

- **hr_res:** for each window, draw a development pair by the R06 sampler (unit uniform, then pair uniform within unit)
  and use that pair's HR resolution.
- **Window:** 256 × 256 px at that hr_res, at a uniformly random position inside the block, rejected and redrawn if
  less than 50 % of its area has valid LR.
- **Input:** the R06 builder path unchanged (area-average to native LR cells, bicubic to px, per-window normalisation by
  mu_lr and s_lr, LR-validity channel).
- **FiLM vector:** [log₂ cell, log₂ hr_res, log₂ s_lr, log₂ |mu_lr|], with cell = the block's cell size.
- **V2 product channels:** built by the R06 V2 rules from the block's `ship_products_v2_1/` (zero channel and zero mask
  where not usable).

**Equivalence test (required, §0.1 item 5).** Run the pretraining window builder on 200 windows drawn from development
pairs' own `lr.tif` (positions and hr_res taken from R06's input records). The output must be byte-identical to the
R06 input arrays for x, the validity channel, the FiLM vector and the V2 channels. Report the result. If it fails,
stop.

### 1.5 Staging

Build a pretraining window cache on scratch before training: windows pre-extracted to arrays in shards, with a
manifest. The training job reads only the cache. No training job reads OAK tars directly (§6).

## 2. Pretraining

### 2.1 Model

- **Body:** the R06 HetUNetClean body with FiLM, unchanged (V1: 1,914,081 parameters; V2: the same plus the ship-product
  branch).
- Pretrain **two bodies**, one with the V2 branch (P-V2 body) and one without (P-V1 body). Each receives only the inputs
  its round-1 counterpart receives.

### 2.2 Pretext objective (pre-registered; one objective, no variants)

The loss is the sum of two terms, each computed in standardised units:

1. **Masked-cell reconstruction.** Before interpolation, mark 30 % of the window's valid LR cells as missing, chosen
   uniformly. They enter the input exactly as missing LR does in development (x = 0, validity = 0). The target is the
   normalised bicubic field the builder produces from the unmasked window; the loss is MSE over the px of the masked
   cells.
2. **Sub-cell sounding spread.** On windows from blocks with usable products, regress log₁₀ `ship_rsd` aggregated to
   the 4 × 4 block grid of the central tile (area-weighted median of the cells covering each 32-px block; non-covered
   blocks masked). The target is standardised by the training-set mean and SD of log₁₀ `ship_rsd`, and the loss is MSE.
   - For the P-V2 body, `ship_rsd` is removed from the input product channels (its channel and mask set to zero) on
     every pretraining window, so the term cannot be solved by copying the input.

Each term has its own small head (a 1 × 1 conv head on the decoder output for (1); the R06 block-head structure for
(2)). Heads are discarded after pretraining.

### 2.3 Schedule

- **60,000 optimizer steps, batch 64,** AdamW, lr 2e-4, weight decay 1e-4, cosine to 1e-6, grad-clip 1.0, bf16
  autocast, the 8 square symmetries as augmentation. Seed 20261007.
- **Final checkpoint is used.** No early stopping, no checkpoint choice.

**Pilot first:** 2,000 steps of the P-V1 body. Report wall time and the pretext losses at steps 0, 500, 1,000 and
2,000 on the held-out cruises. Stop and report as a HOLD if either term's held-out loss is not below its step-0 value
at step 2,000.

### 2.4 Pretext report

For each body:
- training and held-out loss curves for both terms;
- on the held-out cruises: Spearman ρ between predicted and actual log₁₀ `ship_rsd` per block, and the reconstruction
  MSE against a baseline that fills masked cells with the window's mean;
- one QC figure per body of 6 held-out windows (input, masked cells, reconstruction, `ship_rsd` predicted vs actual).

## 3. Fine-tuning

### 3.1 Arms

| arm | initial weights | everything else |
|---|---|---|
| **P-V1** | P-V1 body; a new R06 block head (last layer zero-initialised) | identical to R06 V1 |
| **P-V2** | P-V2 body including its product branch; a new R06 block head | identical to R06 V2 |

"Identical" means the `phase2-r1` training code, with one added option that loads initial body weights. Same 16
leave-one-unit-out folds, sampler, augmentation, within-pair-centred loss, 8,000 steps, optimiser and schedule, final
checkpoint, plus the all-unit model for EW0207. During fine-tuning, `ship_rsd` is an input to P-V2 as in R06.

### 3.2 Seeds

- P-V1: seeds 20261002, 20261003, 20261004 (R06 V1's seeds).
- P-V2: the same three seeds.
- **Scratch V2 seed completion:** train R06 V2 from scratch with seeds 20261003 and 20261004 (the R06 code unchanged,
  init none), so that V2 also has three seeds.

The scratch V1 arm is R06's V1 (three seeds), reused as is.

### 3.3 Scratch-equivalence test (required)

Before any fine-tuning, run the new training code with init = none on **V1, fold lu00, seed 20261002**, on the same GPU
type R06 used for that fold (from its `train_log.json`). Compare the block predictions with R06's.
- Expected: identical.
- If not identical: report the maximum absolute difference and stop as a HOLD.

This shows that R06 V1 is a valid scratch arm for this code.

## 4. Pre-registered comparisons and how they are read

All scoring is by `eval_v1_1.py` only (frozen), on A_fine at tile scale unless stated, using seed-averaged predictions
(mean of log₁₀ block predictions over the three seeds; tile = RMS of blocks, as in R06).

### 4.1 Primary comparison

**P-V1 (seed-averaged) − V1 (seed-averaged, R06):** median Δρ, 95 % bootstrap CI over units, units better of 16,
one-sided sign-test p.

**Reading rule, fixed now:**
- "Pretraining improves ranking" only if the CI's lower bound is above 0.
- "No detectable effect" if the CI includes 0.
- "Pretraining worsens ranking" only if the CI's upper bound is below 0.

Report the units-better count and the sign test alongside, without changing the reading.

### 4.2 Secondary comparisons (reported, not used to reverse the primary reading)

1. **P-V2 − V2**, both seed-averaged over three seeds.
2. **Each of P-V1, P-V2, V1, V2 against the bar** (GBT_ship, 0.510), with the R06 statistics.
3. **Seed spread** of P-V1, P-V2 and V2 (three seeds each), next to R06 V1's 0.023.
4. **EW0207:** the one-unit table for all four arms (all-unit models).
5. **Native 7 units against R02 σ_m (LOUO).**
6. **Block scale:** A_fine/block for all four arms.
7. **Per-unit table** of A_fine/tile ρ for the four arms, GBT_ship, ref_s_lr and ref_C, with each unit's median A_fine
   and the low-amplitude marker.

### 4.3 What this directive does not decide

- It does not adopt a model, and it sets no adoption criteria.
- The R06 note applies: selecting among variants on the same 16 units biases the winner's development score upward. The
  report states this.
